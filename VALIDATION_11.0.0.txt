IMPLEMENTATION SCOPE
- Preserves Electron and the previous appId/product identity used for user-data continuity.
- Personal profile retains persist:web and the existing nova-state key.
- Additional profiles use separate persistent Chromium partitions and namespaced renderer state.
- Vault encrypts stored passwords with Electron safeStorage when available; no autofill is included.
- Capsules exclude cookies, credentials and authenticated sessions.
- App Center stores shortcuts and opens isolated web-app windows; it is not a Windows executable store or universal PWA installer.
- Actions only open validated HTTP(S) URLs; no arbitrary scripts or shell commands. Custom themes can be shared as constrained JSON data, not executable packages.
- App Center web-app sessions ask separately before granting camera, microphone, geolocation or notifications; they do not inherit the main browser Shield filtering or counters.
- Direct CRX loading and complete Chrome extension API compatibility are not claimed.
- Setup is configured as per-user and non-elevated; Portable is configured with separate data.
- Release workflow creates latest.yml for Setup updates; Portable updates are manual.

DEPENDENCY NOTE
- The original project has no package-lock.json. Generating one could not be completed in this environment because the npm registry request timed out. The GitHub workflows therefore use npm install with pinned direct dependencies rather than npm ci. A committed lockfile is still recommended before a stable release.

This report distinguishes static source checks from platform/runtime verification. Passing static checks does not guarantee that all runtime behavior is correct on every Windows system.
